# 3D-модель и окружение

В проекте используется собственная, небрендированная модель кроссовка. Геометрия генерируется скриптом `scripts/generate-model.mjs`, а результат сохранён в `public/models/shoe.glb`. Для запуска приложения моделирование и загрузка сторонних ресурсов не нужны.

## Параметры

| Свойство                | Значение                         |
| ----------------------- | -------------------------------- |
| Формат                  | glTF 2.0, бинарный GLB           |
| Размер                  | 1 539 904 байт, около 1,47 MiB   |
| Треугольники            | 61 556                           |
| Меши / материалы        | 11 / 11                          |
| Настраиваемые части     | `body`, `sole`, `lace`, `tongue` |
| Координаты              | Y вверх, носок направлен по −X   |
| Границы, min            | `[-1.8726, 0.0025, -0.6794]`     |
| Границы, max            | `[1.6063, 1.3999, 0.6794]`       |
| Внешние зависимости GLB | Нет                              |
| Draco / Meshopt / KTX   | Не требуются                     |

Модель содержит отдельный верх, открытый мягкий воротник с внутренней подкладкой, язычок, перекрёстные шнурки с петлями, люверсы, накладки, швы, подошву с фасками и протектор. Мелкие рёбра вязки выполнены геометрией. Это самостоятельная стилизованная модель для конфигуратора, а не скан промышленного изделия.

Каждый меш содержит glTF `extras.part`. После загрузки Three.js читает это поле как `mesh.userData.part`. Материалы также содержат `extras.part` и `extras.shade`: множитель оттенка сохраняет более тёмные накладки и светлые швы при изменении основного цвета.

## Бюджет и оптимизация

Генератор создаёт 188 геометрических секций (оболочки, швы, шнурки, накладки и протектор), затем объединяет секции одного материала в 11 мешей. Это сокращает число геометрических объектов в GLB с потенциальных 188 до 11. Число вызовов отрисовки всей сцены зависит от дополнительных проходов и теней; указанное число мешей не является замером FPS.

В первой итерации модель занимала 1 530 164 байт и имела 61 236 треугольников. После визуальной проверки исправлены пропорции, посадка шнурков, воротник и боковые детали. Финальный файл занимает 1 539 904 байт и содержит 61 556 треугольников: прирост 9 740 байт относится к исправлению формы, а не к оптимизации веса. Сжатие Draco не применяется, поскольку модель уже значительно ниже бюджета 8 MB и загружается без декодера.

## Пересборка

После `npm ci`:

```sh
node scripts/generate-model.mjs
```

Скрипт записывает GLB и выводит размер, количество треугольников, имена частей и границы. Исходные размеры и цвета находятся в начале скрипта; форму задают массивы `widths`, `heights`, `openings` и контур `outline`. Экспорт не требует Blender.

## Замена моделью из Blender

1. Сохранить новую модель как `public/models/shoe.glb` с Y-up и носком по −X. Сцена автоматически нормализует размер.
2. Разделить геометрию по четырём частям. У каждого меша установить custom property `part`: `body`, `sole`, `lace` или `tongue` и включить экспорт custom properties. Резервный вариант — сохранить префиксы имён из таблицы.
3. Оставить отдельные экземпляры материалов для независимого перекрашивания. Использовать белый базовый цвет; тёмные детали описывать числом `shade` в custom properties материала.
4. Экспортировать GLB с материалами, UV и нормалями. Предпочесть встроенные ресурсы; максимальный бюджет модели — 8 MB.
5. Проверить все четыре части, выбор кликом, прозрачность, UV, освещение, мобильный экран и сохранение цвета в PNG. Указать источник и условия использования в `public/assets-LICENSE.txt`.

## HDRI

`public/environment/studio-512.hdr` — уменьшенная версия [Studio Small 03](https://polyhaven.com/a/studio_small_03), автор Greg Zaal, Poly Haven. Лицензия [CC0](https://polyhaven.com/license) разрешает использование, изменение и распространение. Ссылка на исходный файл и описание преобразования сохранены в `public/assets-LICENSE.txt`.

Исходник 1024 × 512 занимает 1 686 299 байт и хранится в `public/environment/studio.hdr` для больших экранов. Мобильная версия 512 × 256 занимает 423 049 байт: на 74,91% меньше данных и на 75% меньше пикселей для декодирования и подготовки освещения. Сцена выбирает подходящую версию; оба файла доступны локально.

Скрипт `node scripts/resize-hdri.mjs` декодирует RGBE в линейные значения `Float32`, усредняет блоки 2 × 2 и сохраняет Radiance RGBE с RLE. Тональная компрессия, гамма-коррекция и обрезка светов не применяются. Повторное декодирование проверяет конечность и знак всех значений; измеренное изменение суммарной RGB-энергии составляет 0,000974%. Максимальное линейное значение после усреднения — 3517,74, что подтверждает сохранение HDR-диапазона. Эти показатели описывают файл; ускорение страницы проверяется отдельно в браузере.

HDRI используется для освещения и отражений; фон интерфейса задаётся отдельно. Локальный путь обеспечивает работу без CDN и внешних декодеров.
