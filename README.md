# FORMA Studio

[![CI](https://github.com/illidan111/3d-shoes/actions/workflows/ci.yml/badge.svg)](https://github.com/illidan111/3d-shoes/actions/workflows/ci.yml)

3D-конфигуратор кроссовка: четыре настраиваемые части, готовые палитры, сравнение A/B, история изменений, ракурсы камеры, ссылка на конфигурацию и экспорт PNG. Новые инструменты добавлены в desktop-интерфейс внутри существующей светлой студии; мобильный интерфейс не входит в эту доработку.

**Локальное демо:** после `npm ci` и `npm run dev` открыть [FORMA Studio](http://localhost:5173).

![FORMA Studio — палитры, сравнение, ракурсы и экспорт](docs/desktop-v2.png)

[Обновлённый концепт desktop](docs/design-desktop-v2.png) · [Проверка desktop-сценариев](docs/desktop-features-verification.json).

Архивная [временная публикация Vercel](https://rushing-tundra-vr3u7th.tmp.now) относилась к базовой версии. Её срок истёк 26 октября 2026 в 10:43 UTC (16:43 UTC+6); это не действующее демо текущей версии.

[Мобильное превью базовой версии](docs/mobile-preview.png). На экране до 768 px стандартная пара сначала показывается изображением: кнопка «Открыть 3D», выбор детали, цвета, материала или сброс вида запускают интерактивную сцену. Ссылка с изменённой конфигурацией сразу загружает 3D, чтобы показывать именно сохранённую пару. На широком экране сцена запускается автоматически. Изменение мобильного потока и его повторное измерение находятся за рамками текущей desktop-доработки.

## Возможности

- Корпус, подошва, шнурки и язычок: девять цветов, три PBR-материала, плавный переход между вариантами.
- Четыре готовые палитры: «Монохром», «Песок», «Ночной город», «Акцент». Каждая применяет конфигурацию всех частей одним отменяемым шагом.
- Сравнение A/B: «Запомнить A» сохраняет независимый снимок до перезагрузки; «Показать A» и «Вернуться к B» переключают варианты. Правка во время просмотра A создаёт новый B, сохраняя A; переходы конфигурации доступны через undo/redo.
- Выбор детали на модели или в панели; камера приближает выбранную часть. Ручное вращение сразу прерывает автоматический подлёт.
- Три готовых ракурса: «Три четверти», «Сбоку», «Сверху». Сброс возвращает общий вид; ручной жест снимает выбор готового ракурса.
- Undo/redo до 50 шагов. Изменения одной детали с интервалом до 400 мс объединяются. Работают Ctrl/⌘ Z и Ctrl/⌘ Shift Z.
- Конфигурация сохраняется в URL. Пример: `?body=olive-metallic&sole=white-matte&lace=navy-glossy&tongue=black-matte`.
- PNG текущего ракурса: «Экран» сохраняет текущее разрешение canvas, «2048 px» — 2048 пикселей по длинной стороне с сохранением пропорций. В имени есть ключ конфигурации; копирование ссылки имеет ручной fallback при недоступном Clipboard API.
- Прогресс загрузки, повторная загрузка при ошибке, статичное изображение без WebGL, восстановление после потери графического контекста.
- Навигация Tab/стрелками, живые объявления изменений, системная настройка уменьшения движения. На узком экране панель располагается под сценой.

## Запуск и проверки

```sh
npm ci
npm run dev
```

Открыть адрес, который напечатает Vite, обычно `http://127.0.0.1:5173`. Для проверки production-сборки:

```sh
npm run build
npm run preview
```

```sh
npm run check
```

Команда последовательно проверяет ESLint, форматирование, тесты, TypeScript и production-сборку; при ошибке останавливается. Для отдельной проверки доступны `npm run lint`, `npm run format:check`, `npm run typecheck` и `npm test`.

Набор тестов охватывает URL и гидратацию, историю, атомарное применение палитр, неизменяемость снимка A, переключение и редактирование A/B, ракурсы, размеры PNG и восстановление renderer после экспорта, клавиатуру, radio-группы, диалоги, Clipboard API и существующий отложенный запуск сцены. Результаты новых desktop-сценариев — в [отдельном протоколе](docs/desktop-features-verification.json). Старые 12 браузерных сценариев и мобильная проверка относятся к `45fecee`, а не к повторному аудиту этой версии. GitHub Actions повторяет проверки и сборку на PR и push в `main`/`master`; наличие workflow само по себе не означает, что удалённый запуск уже состоялся.

## Ключевые решения

**Сцена и интерфейс связаны через Zustand.** `configStore` хранит пользовательский результат и историю, `uiStore` — готовность сцены, наведение и команды экспорта/сброса камеры. React-компоненты подписываются селекторами на нужные поля; материалы и камера обновляются в `useFrame` без `setState` на каждом кадре.

**Модель клонирует изменяемые материалы.** `useGLTF` кэширует ресурс, поэтому изменение общего материала могло бы испортить другие экземпляры. Геометрия остаётся общей, материалы принадлежат экземпляру и освобождаются при размонтировании. Границы `Box3` задают центр и масштаб автоматически.

**Rim-эффект расширяет стандартный PBR-материал.** `onBeforeCompile` добавляет подсветку силуэта, сохраняя HDRI, шероховатость, металличность и tone mapping. Компромисс: вставки привязаны к shader chunks Three.js и требуют проверки после обновления. [Построчный разбор](docs/engineering.md#шейдер-построчный-разбор).

**URL — переносимая конфигурация.** Значения проверяются на границе приложения. `replaceState` обновляет адрес без создания отдельной записи браузера для каждого клика. `localStorage` не нужен: скопированная ссылка воспроизводит результат в другой вкладке.

**Палитры и сравнение используют общую историю.** `applyConfig` валидирует и копирует полную конфигурацию, добавляя один шаг независимо от числа изменённых частей. Снимок A отделён от редактируемого состояния и заморожен; URL и PNG отражают видимую конфигурацию. Снимок и режим сравнения в ссылку не входят.

**PNG сохраняет цвет экранного рендера.** `preserveDrawingBuffer` выключен. После завершения перехода материалов приложение рендерит сцену в default framebuffer и синхронно копирует пиксели в отдельный canvas. Для 2048 px оно временно меняет drawing buffer, затем в `finally` восстанавливает размер, DPR, viewport, scissor и render target до асинхронного `toBlob`. Камера, CSS, tone mapping и гамма остаются прежними; HTML-панель не экспортируется.

**Качество адаптируется.** DPR ограничен 2 на широком экране и 1,5 на узком; при устойчивом падении FPS `PerformanceMonitor` снижает его до 1. Мобильная сцена использует HDRI 512 px и тень 512 вместо desktop HDRI 1K и тени 1024. Тень статичной геометрии рассчитывается один раз; скрытая вкладка приостанавливает цикл рендера.

**Мобильный старт требует решения пользователя.** Сначала загружаются интерфейс и статичное превью; пользовательская активация подгружает отдельный чанк `React.lazy`. Это уменьшает начальную работу CPU/GPU для посетителя, который ещё не открыл 3D. `compileAsync` подготавливает шейдеры до запуска цикла кадров; одной этой подготовки оказалось недостаточно для целевого Lighthouse. Поэтому мобильный поток изменён явно для всех пользователей, без определения аудитора или таймерной задержки. Стоимость запуска 3D сохраняется после активации и измеряется отдельно.

## Архитектура и развитие

```text
src/
  components/scene/  Canvas, Model, CameraRig, Loader, SceneRuntime
  components/ui/     Panel, Presets, ComparisonControls, CameraViews, ExportOptions и другие контролы
  config/            части, цвета, материалы, готовые палитры, ракурсы, пути модели и HDRI
  stores/            конфигурация/история и временное состояние интерфейса
  lib/               URL, PNG, доступность, radio-навигация
  shaders/           GLSL-вставки для подсветки силуэта
  hooks/             синхронизация URL, reduced motion
  tests/             логика, DOM и интеграция
scripts/             генерация модели и подготовка HDRI
docs/                устройство проекта и измерения
```

[Инженерный разбор, типичные ошибки и учебный план](docs/engineering.md). [Устройство модели и её замена](docs/model.md). Модель собственная, небрендированная; HDRI Poly Haven распространяется по CC0. Источники и лицензии — в [assets-LICENSE.txt](public/assets-LICENSE.txt).

## Что можно объяснить на собеседовании

Проект показывает границу между React-состоянием и GPU-анимацией; владение материалами при кэшировании ресурсов; разницу между цветом, roughness и metalness; работу нормалей в пространстве камеры; проверку внешних URL; транзакции истории; доступность сложного визуального интерфейса. Эти решения разобраны с привязкой к исходникам, чтобы формулировки можно было подтвердить кодом.

Дальнейшие улучшения: измерить энергопотребление и рассмотреть `frameloop="demand"` с корректной инвалидацией; добавить профессиональную модель с UV и текстурами; проверить KTX2 на физических устройствах; расширить браузерные тесты WebGL; проверить экранные дикторы и контраст вручную. Каждое изменение стоит сравнивать с зафиксированной базовой версией.

## Vercel

В репозитории есть `vercel.json`: framework Vite, build `npm run build`, output `dist`. После авторизации владельца можно импортировать репозиторий в Vercel или выполнить `npx vercel` из его каталога. Базовая версия публиковалась через `vercel deploy --temporary`; срок той публикации истёк 26 октября 2026 в 10:43 UTC. Публичного постоянного адреса текущей desktop-версии здесь не заявлено.

Для актуального результата используйте локальный запуск выше. Постоянное размещение требует настройки аккаунта Vercel. Измерения на физическом телефоне остаются отдельной задачей; статус CI доступен в GitHub Actions.
